# Phase 3: Blog: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a blog at `/blog`. A post is one Markdown file. The blog stays hidden until the first post is published.

**Architecture:** A small build script reads `content/blog/*.md`, checks each post, turns it into HTML, and writes one JSON file. The pages import that JSON as plain data. So nothing reads a file when the site runs, and the Markdown libraries never reach the Cloudflare Worker. The menu link, the home section, the sitemap, and the `noindex` flag all depend on one thing: the number of published posts.

**Tech Stack:** Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4, Node built-in test runner. Three new build-time packages: `marked`, `katex`, `highlight.js`.

**Spec:** `docs/superpowers/specs/2026-11-21-site-upgrade-design.md` (sections 3, 5, 7, 8, 10, 12).

## Why a build script, and not "read the files in the page"

`open-next.config.ts` sets no page cache. So the Worker may render a page again when a visitor asks for it. At that moment there is no `content/` folder. A page that reads files would then fail or show an empty blog.

With the build script, the posts are data inside the bundle. A page renders the same at build time and at run time.

## Why these three packages

The spec says: use the smallest set that covers code highlighting and math.

| Package | Job | Its own dependencies |
|---|---|---|
| `marked` | Markdown to HTML, with tables | none |
| `highlight.js` | Colors in code blocks | none |
| `katex` | Math formulas | one (`commander`, used only by its command line tool) |

We write three small pieces ourselves instead of adding more packages: the reader for the details block at the top of a post (about 20 lines), the glue for code colors (about 6 lines), and the glue for math (about 25 lines). Each has tests.

## Global Constraints

- Work only on the branch `phase-3-blog`.
- **A push to `main` publishes the live site.** Never push or merge to `main`. The branch is pushed once, at the end, to open the pull request. Do not merge the pull request.
- New packages: only `marked`, `katex`, `highlight.js`, all in `devDependencies`. They run at build time only.
- Never invent a post, a client, or a number. The only post this plan adds is the sample, with `draft: true`. Its text explains how to write a post.
- Every page is static. No code reads a file at run time. No runtime image optimizer.
- Dark only. Use the tokens in `src/app/globals.css`: `bg-page`, `bg-surface`, `border-line`, `text-ink`, `text-bright`, `text-muted`, `text-accent`, `text-accent-bright`. No new color values.
- No emoji. Icons come from `src/components/ui/Icon.tsx`. No `animate-` class, no `opacity-0`, no `outline-none`, no `scroll-smooth`.

- One `h1` per page. Every page has its own title, description, and canonical address.
- `src/data/seo.ts` and `src/data/blog.ts` have no value imports. `import type` is fine. Node runs them directly in tests.
- A file with `"use client"` must never import `@/data/posts`. That would send every post to the browser.

- Plain words in all site text. No "cutting-edge", "revolutionize", or "seamless".

## Review Focus

These can hurt a visitor or the owner. Each one has a test or a check in the task that owns it.

1. **Zero published posts.** This is the state at launch. Expected: the build passes, `/blog` shows "No posts yet" and is `noindex`, the menu has no "Blog" link, the sitemap has no `/blog`, the feed is valid and empty, and `/blog/anything` is a 404. Tests in Task 3. Build check in Task 5.
2. **A draft reaches the live site.** Expected: never. The build script leaves drafts out unless it gets `--drafts`, and `pnpm build` always writes the JSON again. Test in Task 1. Check in Task 5.
3. **A bad post.** A missing detail, a misspelled key, a wrong date, a `# ` heading (a second `h1`), a broken formula, or Windows line endings. Expected: `pnpm test` and `pnpm build` stop with a message that names the file and the problem. Nothing half-right is published. Tests in Tasks 1 and 2.
4. **Text that looks like syntax.** "It costs $5 and $10" is not a formula. A title with a colon, `&`, or `<script>` must not break the details block, the feed, or the structured data. Tests in Tasks 1 and 3.
5. **Phone width (375px).** A wide table, a long code line, or a big formula pushes the page wider than the screen. Expected: the block scrolls inside its own box. The page never scrolls sideways. Browser check in Task 5, with the sample post.

import test from "node:test";
import assert from "node:assert/strict";
import { parsePost, renderMarkdown, selectPosts, buildPosts } from "./blog.mjs";

const good = {
	title: "A title",
	description: "One sentence.",
	date: "2026-12-01",
	audience: "leaders",
	topic: "ai-engineering",
	author: "Dr. Veysel Kocaman",
};
const file = (details = {}, body = "First line.\n") => {
	const head = Object.entries({ ...good, ...details })
		.filter(([, v]) => v !== undefined)
		.map(([k, v]) => `${k}: ${v}`)
		.join("\n");
	return `---\n${head}\n---\n\n${body}`;
};

	assert.equal(p.date, "2026-12-01");
	assert.equal(p.draft, false);
	assert.equal(p.image, "/images/blog/x.webp");
	assert.equal(p.body.trim(), "First line.");

	const posts = [
		{ slug: "b", date: "2026-01-01", draft: false },
		{ slug: "d", date: "2026-03-01", draft: true },
		{ slug: "c", date: "2026-02-01", draft: false },
		{ slug: "a", date: "2026-01-01", draft: false },
	];

	assert.deepEqual(selectPosts(posts, { drafts: true }).map((p) => p.slug), ["d", "c", "a", "b"]);

test("buildPosts skips other files and drafts, and keeps the body out of the list", () => {
	const files = [
		{ name: "one.md", raw: file({ date: "2026-01-01" }) },
		{ name: "two.md", raw: file({ date: "2026-02-01", draft: "true" }) },
		{ name: ".DS_Store", raw: "junk" },
	];
	const out = buildPosts(files, { drafts: false });
	assert.deepEqual(out.posts.map((p) => p.slug), ["one"]);
	assert.equal(out.posts[0].body, undefined);
	assert.deepEqual(Object.keys(out.html), ["one"]);
	assert.match(out.html.one, /<p>First line\.<\/p>/);
	assert.equal(buildPosts(files, { drafts: true }).posts.length, 2);
});

test("renders headings, links, images, and tables", () => {
	const html = renderMarkdown("## Part\n\n[a](https://example.com) ![alt](/images/blog/x.webp)\n\n| a | b |\n|---|---|\n| 1 | 2 |\n");
	assert.match(html, /<h2>Part<\/h2>/);
	assert.match(html, /<a href="https:\/\/example\.com">a<\/a>/);
	assert.match(html, /<img src="\/images\/blog\/x\.webp" alt="alt">/);
	assert.match(html, /<table>[\s\S]*<td>2<\/td>/);
});

test("colors code, and escapes code in an unknown language", () => {
	const py = renderMarkdown("```python\ndef f(x):\n    return x\n```\n");
	assert.match(py, /<pre><code class="hljs language-python">/);
	assert.match(py, /class="hljs-keyword">def</);
	const plain = renderMarkdown("```nolang\n<b>&</b>\n```\n");
	assert.match(plain, /&lt;b&gt;&amp;&lt;\/b&gt;/);
	assert.doesNotMatch(plain, /<b>/);
});

test("renders math, inline and as a block", () => {
	assert.match(renderMarkdown("Energy is $E = mc^2$ here."), /<p>Energy is <span class="katex">/);
	assert.match(renderMarkdown("$$\n\\frac{a}{b}\n$$\n"), /class="katex-display"/);
});

test("text that looks like math stays text", () => {
	assert.doesNotMatch(renderMarkdown("It costs $5 and $10 per user."), /katex/);
	assert.doesNotMatch(renderMarkdown("A price of \\$5 or \\$x\\$."), /katex/);
	assert.doesNotMatch(renderMarkdown("Run `echo $HOME $PATH` now."), /katex/);
	assert.doesNotMatch(renderMarkdown("```\n$a$\n```\n"), /katex/);
});

test("a broken formula stops the build", () => {
	assert.throws(() => renderMarkdown("$\\frac{a$"));
});

- [ ] **Step 4: Write `src/lib/blog.mjs`**

Rules that the signature and the tests do not fix:

- The details block: the file starts with a `---` line and the block ends at the next `---` line. Each line is `key: value`, split at the first colon. A value in quotes keeps everything inside the quotes. Otherwise ` #` and what follows is a comment. Blank lines are fine.
- Allowed keys: `title`, `description`, `date`, `audience`, `topic`, `author`, `draft`, `image`. Any other key is an error. Required: the first six.
- `audience`: `leaders` or `research`. `topic`: `ai-engineering`, `platform-engineering`, or `data-science`. `draft`: `true` or `false`. `image`: starts with `/`. `date`: `YYYY-MM-DD` and a real day.
- The file name (slug) matches `^[a-z0-9]+(-[a-z0-9]+)*$`.
- A level 1 heading in the body is an error. The message tells the writer to start at `##`, because the title is the page's `h1`. Find it with `marked.lexer`, so a `#` line inside a code block does not count.
- Markdown: one `Marked` instance. `renderer.code` uses `hljs.highlight` when `hljs.getLanguage(lang)` exists, and escaped plain text otherwise. Import from `highlight.js/lib/common`.
- Math: two `marked` extensions that call `katex.renderToString` with `throwOnError: true`. Block: `$$ ... $$` on its own lines, with `displayMode: true`. Inline: `$...$` where the character after the first `$` and the character before the last `$` are not spaces, and the character after the last `$` is not a digit. A `$` after a backslash never starts a formula.
- Raw HTML inside a post passes through. Posts come from this repository, so the writer is trusted. Say so in a comment.

## Changes made while building

The checks in Task 5 found two problems in this plan. Both are fixed in the code, and each has a test.

1. **`dynamicParams = false` is gone (Task 4).** On the Cloudflare runtime it made every post a 404. That setting serves posts only from the Next.js page cache, and this site has no page cache on Cloudflare. The post page calls `notFound()` for an unknown address instead.
2. **Client components must not import the `@/components/ui` index.** The contact form did. The index also exports the Header, which imports the post data. So the text of every post went into the home page script. Now `src/data/posts.ts` imports `server-only` (the build fails on a leak), and the test in Task 4 also forbids index imports in client files.

Two small additions: a "Draft" label on draft posts under `pnpm dev`, and a dark scroll bar on code blocks and tables.

## Left out on purpose

Add these when there is a real need.

- Comments, search, newsletter signup, page numbers, a topic filter (spec, section 3).
- Links on headings, a table of contents, "related posts".
- Width and height on images inside posts. The browser sizes them. A post image can shift the text a little while it loads.
- Posts that publish by themselves on a future date. The site is static. A post is live when its file is deployed without `draft: true`.
- One JSON file holds all posts. This is fine for some hundreds of posts. Split it per post when the Worker gets too big.
